About

aka, Why did you build a CSS framework in 2026?

In a world filled with new technologies and frameworks like Tailwind, the existence of many other feature-complete CSS frameworks like Bulma and Bootstrap, and the ever-increasing popularity of making robots do all of the creative thinking for you, who in their right mind would make a whole new CSS framework by hand?

CSSIsInUse was created for a few reasons:

  1. I liked other frameworks, but they didn't quite have all the features I wanted.
  2. Writing a bespoke CSS file by hand for every project was grating.
  3. Tailwind makes my head hurt.
  4. I like making stuff.
So what makes it unique?

CSSIsInUse is a semantic-where-possible, genetic, accessible-by-default framework with infinite themability.

Semantic-Where-Possible

In cases where CSSIsInUse can gently suggest that you use the correct semantic HTML elements when possible, it will do so. Sometimes that means it simply styles that element without an option for a class and expects you to just use it, and othertimes when the element itself is generic enough that it can be used in different ways, it uses the element's name to suggest when to use it.

A good example of this are tables. There is no class for a table, you just make it and it's there.

Genetic

All variables, numbers, colors, paddings, corner-roundednesses are all derived from a few common ancestor variables. The base padding is 1rem, and all paddings are multiples of that base, so if you create a theme that sets the base to 2rem, all padding sizes are changed accordingly. This doesn't mean you can't override variables when needed, but the entire site will scale and change as you change base values.

Accessible-By-Default

Surprisingly, a lot of frameworks I've looked through are not accessible-by-default. They'll (sometimes) respect the user's dark/light mode preference, but haven't set up prefers-contrast, reduced-motion, or reduced-transparency features. In CSSIsInUse, those are built in. A CSS framework can't make your site accessible, but all of the default values should be accessible from a visual standpoint.

Infinite Themability

This is the biggest difference between CSSIsInUse and other frameworks. Because of all of the above rules, creating new color schemes is simple and easy. You just create a new class / data-scheme by setting a few variables, register it in the SCSS color system, and all elements will be derived from that changing the entire look and feel of the site. Apply it to the body tag to apply the theme to the entire site, apply it to an element to change the look of that element and all child elements. Each theme automatically includes a light and dark mode, based on user preference or through the data-theme attribute.

Themes simply override the existing variables, so if you want each theme to change fonts, padding sizes, outline thicknesses, etc, that's no problem at all.

Okay, and?

So, because of all of the above rules, you have a simple to use but visually powerful framework that handles the boring stuff and lets you paint it however you want.

Light/dark mode built in, make as many themes as you want your users can apply, a fluid structure that doesn't really rely on breakpoints, and built-in accessibility features.

Even if you hate how this site looks, because you can change it fairly quickly by just modifying a few base variables, it's a great starting point for any project.

Components

Block

A basic spacing tool

The block is a basic spacing tool that allows sibling HTML elements to be spaced apart.

If it is not the final sibling element, it gives the element a margin-bottom.

Example

This top text is in a block.
This middle text is also in a block, which you can see there is a gap between this text and the text below.
This final text is also in a block, but because it's the final sibling, there is no additional margin below it.
<div class="block">
  This top text is in a block.
</div>
<div class="block">
  This middle text is also in a block, which you can see there is a gap between this text and the text below.
</div>
<div class="block">
  This final text is also in a block, but because it's the final sibling, there is no additional margin below it.
</div>

Without a block, there would be no margin between the text.

Example

This top text is not in a block.
This middle text is also not in a block, which you can see because it's touching the text above and below.
This final text is also not in a block, but because it's the final sibling, there is no difference visually.
<div>
  This top text is not in a block.
</div>
<div>
  This middle text is also not in a block, which you can see because it's touching the text above and below.
</div>
<div>
  This final text is also not in a block, but because it's the final sibling, there is no difference visually.
</div>

Because the block component is an SCSS mixin, it is built into many components and elements by default, but also is available as a set of classes which can be applied to any of them to override their default values. Because this is a spacing tool, and we are designers, the spacing is not necessarily consistent. Some elements and components want more space away from other elements than others. To that end, there are multiple block sizes available, shown below.

Example

block-none (0)
block-xs (0.25rem)
--padding-xs: calc(var(--padding-base) * 0.25);
block-small (0.5rem)
--padding-small: calc(var(--padding-base) * 0.5);
block (1rem)
--padding-base: 1rem;
block-large (2rem)
--padding-large: calc(var(--padding-base) * 2);
block-xl (3rem)
--padding-xl: calc(var(--padding-base) * 3);
Just here to show the XL block above it.
<div class="card block-none">
  block-none (0)
</div>
<div class="card block-xs">
  block-xs (0.25rem)
</div>
<div class="card block-small">
  block-small (0.5rem)
</div>
<div class="card block">
  block (1rem)
</div>
<div class="card block-large">
  block-large (2rem)
</div>
<div class="card block-xl">
  block-xl (3rem)
</div>
<div class="card">
  Just here to show the XL block above it.
</div>

Finally, there is the sister tool pre which functions exactly the same way, except it uses margin-top instead if it is not the first sibling element. Only a few elements and components use it by default, usually subtly, but it is another spacing tool in your arsenal.
